# 供应商账号健康守护任务取消保护与执行效率优化设计

## 背景

供应商账号健康守护任务按 Cron 周期执行（当前为每 4 分钟一次）。账号级测试有独立超时，任务级执行也有 `TimeoutSeconds` 超时。当账号数量较多或上游大面积慢响应时，任务级超时可能先于队列中尚未执行的账号触发。

当前实现里，所有目标账号由 `runTargets` 分发到固定数量 worker；一旦任务级 `runCtx` 取消，`tester.runTestBackground` 返回 `context.Canceled`，`supplierAccountHealthGuardEvaluateResult` 会把该结果判定为 `failed`。排在队列中、从未开始测试的账号也会因此累计连续失败次数，达到阈值后会被误禁用调度。

## 目标

1. 任务级取消/超时时，未真正开始测试的账号记为 `skipped`，不累计失败、不触发禁用；已开始但超时的账号维持 `failed`。
2. 将并发上限从 8 提升到 32，允许配置更高并发以缩短单轮耗时。
3. 将单账号超时默认值从 90 秒下调到 30 秒，健康探测无需等待 90 秒才判失败。

## 非目标

- 不修改账号测试本身的平台逻辑。
- 不调整失败/慢响应/恢复阈值语义。
- 不修改任务调度锁和 4 分钟 Cron 行为。

## 方案

### 1. 任务取消保护

`runTarget` 在调用 `runTestBackground` 前检查 `ctx.Err()`：

- 若任务级 ctx 已取消且该账号尚未开始测试，直接返回 `skipped` item，原因为「任务时间不足，本次跳过」，不更新调度状态，不累计失败计数。
- 已进入测试的账号维持现状：测试内部因任务取消返回 `context.Canceled`，仍判为 `failed`（此时请求确实发起过）。

### 2. 并发上限调整

后端 `MaxSupplierAccountHealthGuardConcurrency` 从 8 改为 32；`validateSupplierAutomationTask` 中健康守护并发校验上限同步改为该常量。

### 3. 默认超时下调

后端 `DefaultSupplierAccountHealthGuardTimeoutPerAccountSeconds` 从 90 改为 30；前端配置弹窗默认值、`applyAccountHealthGuardDefaults`、校验上限（并发 1-32）与提示文案同步调整。

## 影响范围

- 后端：`backend/internal/service/supplier_account_health_guard.go`、`backend/internal/service/supplier_automation_service.go`（校验常量引用）。
- 前端：`frontend/src/views/admin/supplier-management/SupplierAutomationView.vue`。
- 测试：`backend/internal/service/supplier_account_health_guard_test.go` 新增/调整用例；前端既有 spec 如有默认值断言需同步。
